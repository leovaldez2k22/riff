# Riff 0.9.0-rc14

> **Historical record.** This document describes earlier work and is kept as it was written. It is not current documentation and may not match the code. Current documents: [documentation index](README.md). Current plan: [Riff excellence implementation plan](RIFF_EXCELLENCE_IMPLEMENTATION_PLAN.md).

Home, Podcasts, Radio and provider mood feeds now retain successful data in process memory and share in-flight requests. Re-entering a tab reads the cached response. Refresh windows follow the phone’s local time at 06:00 and 18:00, including timezone and daylight-saving changes. The cache clears on account changes and removal from recent apps. Cancelling a screen leaves the shared request running; cancelled or obsolete cache generations cannot publish stale data. Failed requests remain retryable. Library requests the current playlist index on every tab entry, retains existing playlist contents, and invalidates deleted or edited collections. A pink thumbs-up on black identifies Liked Music.

The Home tags come from YouTube Music’s browse chips and mood/genre navigation endpoints. Selection curates Home through those provider endpoints, with independently cached feeds and a distinct subtle code-drawn scene for each tag. The selected scene replaces the ambient gradient and fades into black near the screen midpoint. The device supplied 50 tags. Forgotten favourites moves immediately after Quick picks when the provider offers that shelf; if absent, the existing unavailable notice follows the same ordering.

Song menus use one shared multi-select playlist picker in the player, search/catalog, album/playlist and Downloads screens. Saves require provider acknowledgments; HTTP success alone is insufficient. Completed playlists leave the selection while failed selections remain available for retry. A preflight check avoids adding the same video twice. Read-only collections report a failure. Owned playlist rows can remove a song’s precise playlist-entry token after confirmation, allowing authored repeats to remain distinct. A visitor/session refresh cancels only its edit request, returns a retryable failure, and does not leave the entire picker coroutine cancelled.

Playlists and albums have local title/artist search and collection-order, title A–Z/Z–A, artist A–Z and supplied date-added sorting. Searches handle accents and multiple words. Original source indices survive filtering/sorting so playing a result selects its authored position in the complete ordered queue. Downloads exposes the same tools, with real audio commit dates and newest-first default ordering; its hero remains the most recently downloaded artwork. Date sorting is disabled with an explanation when YouTube Music does not supply dates. Playlist numbering is removed, and album/playlist song titles stay on one line with ellipsis.

The UI chooses a supported 60, 90 or 120 Hz rate for its window and frame-rate hints. High-contrast navigation keeps white unselected labels and a low-opacity selector. The navigation pill grows equally above and below its center while its normal icons and labels stay in place. Queue reordering starts immediately from the two-bar handle; a floating row follows the finger, stationary list anchors prevent jumps, and proportionate edge scrolling lets a drag travel further and reverse direction. Stable timeline identifiers preserve repeated authored entries. Accessibility move actions remain available.

Six resizable widget providers offer Compact, Wide, Artwork, Player, Large and Circle layouts. They display the current/restored paused song and app playback controls; Large includes Up next. Artwork is loaded off the main thread and clipped to the design. Empty widgets open Riff. Playback pending intents are explicit, immutable and protected by an app-private control token. Settings lists the designs and asks the launcher to pin one only after the user selects it. Launcher sizing, padding and pin support vary.

The player menu adds 5, 10, 15, 30, 45, 60 and 90 minute sleep timers and a custom 1–1440 minute option. The service owns a monotonic deadline, pauses once on expiry, publishes remaining time and safely cancels/replaces timers. It does not persist a sleep timer across process termination.

## Validation

Verification evidence is retained under `artifacts/features-rc14`. The signed production build passes all 116 unit tests. Full release lint reports zero errors and 73 warnings; new widget warnings are string/resource and style suggestions. Tests cover local 6 AM/6 PM windows, timezone/DST changes, shared-request lifetime, obsolete generations, exact collection invalidation, collection search/order/date handling, partial multi-playlist saves and cancellation, timer expiry/cancellation and queue edge scrolling. Existing audio, offline seeking, original-audio, lyrics, video and queue regression tests remain green. Test-only preview activities live in `src/verification` and are included only with the explicit `releaseSmoke` build property; the production APK excludes them.

Physical checks on the I2217 confirm cache reference reuse across Home (12 shelves), Podcasts (3), Radio (2) and a mood feed (3), with 50 provider tags. A fresh Library scan returned 15 playlists and retained the same cached four-song Chill Music collection and four exact removal tokens. The approved account test created two private test playlists, added Numb to both, read the acknowledged entries, removed each precise entry and read both empty collections, then deleted both playlists. The final index reports no remaining test playlists. An earlier verification playlist was also recovered and removed. Existing user playlists were not edited.

All six widget RemoteViews layouts rendered on the phone. A window requested and reported 90.0 Hz for the isolated high-contrast navigation fixture; labels stayed in place and remained readable while the selector expanded. Its preferences were isolated from the user's settings. Queue touch tests moved a row immediately from index 1 to 4, then verified bottom-edge scrolling from index 6 to 11 and reversal back to 4, retaining all 51 distinct entries and the playing item. The real Media3 dependency also preserves session window UID mappings across moves. Native local playlist search found only the requested authored index; Downloads search/clear and all sort options were checked. The current account had 56 metadata records and no ready offline audio bundles, so populated download sorting and offline seek regression cases are covered by unit tests rather than a new physical download test. Native sleep-timer set/cancel passed. A finite audio-cache test replayed 262,144 bytes with only one upstream open and removed its test entry afterward.

The test process was suspended by the phone while it had no foreground activity, producing long pauses in earlier attempts. Bringing Riff forward allowed the full account test to complete; the instrumentation now launches a foreground activity and clears its temporary keep-screen-on flag afterward. Those early incomplete/failed attempts are retained as diagnostics and are not counted as passes. The source/manifest/DEX check confirms the production APK includes none of the test preview activity or fixture player. Production tab switching passed, the restored mini player retained its seven-item queue, and the final runtime error capture contains no new app crash.

Version code 15, minimum API 31, target API 36 and the Riff label are confirmed. The APK includes arm64-v8a, armeabi-v7a, x86 and x86_64 native libraries. The signing certificate remains unchanged.
