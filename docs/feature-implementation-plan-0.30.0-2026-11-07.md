## 4. Feature designs

Costs below are planning estimates. “Small code” means existing platform/library capabilities with no proposed large dependency; the APK delta is unmeasured. Every new remote call needs a privacy entry naming its host, trigger, fields, credentials and retention. Ordinary playback and deliberate YouTube Music actions keep their existing rules. Examples in tests use synthetic accounts, fixtures and locally generated media.

### 1. Lyric translations · both · 2a

**Today.** LyricsModels.kt:19–35 represents a line, backing voice and document. Its TTML walker at 158–180 discards translations but separately collects romanization. LyricsRomanize.kt:14–31 handles script options. LyricsKaraoke.kt:177–192 draws sung words; PlayerLyricLine.kt:72–92 also distinguishes gaps. LyricsPanel.kt:51 is the full reader. LyricsRepository.kt:383–406 persists documents. AdditionalLyricsProviders.kt:19 selects NetEase word or line lyrics.

**Implementation and settings.** Inventory real, permitted TTML samples and NetEase translation fields, including language and timed alignment; distinguish observed provider support from a sample with no translation. Add optional language-tagged translations to the owning line. Tie by provider line ID or validated timestamp within the same recording; ambiguous matches stay empty. Keep old caches readable and allow stale entries to refresh. The lyrics button toggles text directly beneath each original. Original timings drive scroll, sweep, blur and backing vocals; translation wraps normally and instrumental dots have no translation. Apply Q1 to language, fallback and the romanization layout.

**Cost, privacy and acceptance.** Small shared code and larger cached lyric documents, with bounded text lengths. Provider fields add minimal parsing work. Under the recommended option no new permission, service or lyric upload. Test translated TTML, duplicate timestamps, overlapping singers, old offline caches, untranslated tracks, simultaneous romanization, TalkBack and large fonts. Check that a line never lights up early because translated text has different length.

<a id="feature-2"></a>

### 2. Last.fm and ListenBrainz scrobbling · both · 4a

**Today.** ListeningHistory.kt:48–63 qualifies once when a track starts playing. EncoreStore.kt:148–176 accumulates heard time after a play is registered. MusicPlaybackService.kt:238–282 and 494 onward see transitions and history. A history row alone would submit early and miss seeks, pauses or an account change.

**Implementation and settings.** Attach a separate listening counter to service playback. Count elapsed audible time, cap discontinuities and reset on a real repeat; a seek forward earns no extra time. Match Last.fm's rule for tracks longer than 30 seconds, half the track or four minutes, whichever comes first. Use ListenBrainz single/import payloads and a separate ephemeral playing-now message if approved. Capture start timestamp, scoped play ID and provider. On threshold, persist a bounded per-service pending row once; acknowledge only confirmed records, back off on 429/offline, isolate permanent failures and ambiguous timeouts. Never promise remote exactly-once delivery after a lost acknowledgement. Disconnect revokes local tokens and clears that service’s pending data. No history backfill or Encore schema changes.

**Cost, privacy and acceptance.** Small code plus capped pending rows; batch sends during existing work, avoid a timer per second. Provider-specific opt-in and Q2. Last.fm browser authorization and signed API calls to www.last.fm and ws.audioscrobbler.com; a distributed client signing secret is extractable. ListenBrainz uses a user token at api.listenbrainz.org. Store credentials with Android Keystore protection, omit from export, backup and diagnostics. No new Android permission. Test short tracks, boundary seconds, repeats, buffering, disabled service, token failure, mixed batch results, clock shifts, switch-account mid-send and removal of pending data. [Last.fm rules](https://www.last.fm/api/scrobbling) · [ListenBrainz payloads](https://listenbrainz.readthedocs.io/en/latest/users/json.html)

**Implementation and settings.** Keep settings-off suppression, once-a-day checks and draft/prerelease rules. For updates require the installed edition and a newer official version; for switches require the opposite edition and the exact installed version. Look up that version explicitly if latest is newer. Isolate debug/preview and local signing identities. Parse bounded asset metadata, offer edition and size, ask, then stream to private staging with progress on every transfer (indeterminate until bytes total is known), cancel and space checks. Restrict HTTPS redirects to verified GitHub asset hosts. Release the staged copy after handing bytes to the session; abandon failed sessions, reconcile replacement and clean leftover files on next start. Deduplicate concurrent requests. **Cost, privacy and acceptance.** Small APK code; allow transient storage for staging AND the OS install session. Only a confirmed download consumes transfer energy. Shared REQUEST_INSTALL_PACKAGES special access; GitHub API/feed plus GitHub release asset/CDN requests with no YouTube cookies. Update privacy and the old notice documentation. Preserve page/feed tests, replace the deliberate prohibition with fixtures for spoofed redirects, wrong signer/package/edition, downgrade, stale feed and cancel. Packaging test with disposable signed fixtures for update, same-version switch both ways, failed install, denied permission, reboot/process replacement and cleanup. ### 4. Jump to the most-replayed part · Plus (owner, 8 Nov; was both) · 2c

**Today.** ProviderCatalog.kt:195–229 parses catalog pages. ProviderCatalogRepository.kt:239–263 makes track/queue next requests. There is no playback heatmap parser in the app; EncoreCharts' heatmap plots the listener's weekly hours. Provider coverage on music-only tracks is unknown.

### 6. Bluetooth resume and pause on mute · both · 3a

**Today.** AudioOutputPolicy.kt:4 classifies a route for display; AudioOutputControls.kt:70–86 exposes the output picker. MediaButtons.kt:20–39 controls actions. MusicPlaybackService.kt:230 already enables Media3's pause-on-noisy-output behavior. A connected headset and an actively routed headset are different signals.

**Implementation and settings.** Two independent playback switches per Q6. Observe active output changes in the running media service. Record a short-lived resume ticket only when playback actually stopped after losing Bluetooth output. Bind it to the active owner, queue entry, route where identifiable and elapsed time. Manual pause, playback elsewhere, focus loss, noisy wired disconnect, Cast, timer expiry or process restart invalidates it. Resume only when the matching output is active and playback/focus permits it. Observe media-stream zero volume using supported volume callbacks/active-session checks verified on target phones; cover hardware volume keys and system UI. Avoid polling while idle. Do not infer a mute from a silent song.

**Cost, privacy and acceptance.** Small code, service-lifetime callbacks, no network or stored device names. Try existing audio routing APIs first. If reliable device matching requires BLUETOOTH_CONNECT on Android 12+, return to the owner with the narrower alternative before adding permission. Exercise reconnect, OS media-button auto-play, two headsets, calls, manual pause during reconnection, volume zero and Cast on real hardware. A callback that merely reports connected devices fails the active-route test.

### 7. Search by lyrics · both · 2b

**Today.** LyricsRepository.kt:91–160 fetches by known track and 343–406 reads/writes cached documents. AdditionalLyricsProviders.kt:56–70 handles plain text and priority. SearchSuggestions.kt:45–99 parses ordinary suggestions; ProviderCatalogRepository.kt:487 searches the catalog. LRCLIB's documented q matches metadata. A unique verse absent from the title is the minimum test of an online candidate. [LRCLIB API](https://lrclib.net/docs)

**Implementation and settings.** Add an explicit Search by lyrics action. Index only locally held lyric texts associated with the current owner’s eligible library/downloads; use a normalized derived index with original line references, discard it when corresponding data is removed. Show a matched excerpt and the available recording. For wider search investigate provider capability and usage rights on a set including non-English verses, covers and false positives. Resolve external candidates to YouTube Music by artist/title/version/duration; show uncertain matches for choice. Keep submitted lyric phrases out of ordinary type-ahead, query logs and URLs in diagnostics. Q7 decides required coverage and any external destination. If the trial fails, report the shortfall rather than presenting local coverage as whole-catalog search.

**Cost, privacy and acceptance.** Small code plus index size proportional to locally held text. Build incrementally off the UI thread and cap retention. No new permission. Local mode sends nothing; online mode discloses the submitted phrase and host before use. Test accents, scripts without spaces, punctuation, collisions, empty library, removed downloads, owner change and an unknown song whose title contains none of the entered words.

### 9. Set a downloaded song as ringtone · both · 4b
