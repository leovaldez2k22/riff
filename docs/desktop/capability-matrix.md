# Riff Desktop Capability Matrix

Updated 2 November 2026 during production Phase 1. This replaces earlier labels that confused component presence with end-to-end integration. See [Phase 1 evidence ledger](phase-1-status.md) and [production completion plan](../../reports/Riff%20Windows%20production%20completion%202026-11-02.md). Historical M1–M6 are not the five production completion phases.

| Area | Actual integrated behavior | Open work / acceptance limit |
|---|---|---|
| M1 shell / visual tokens | Frameless Win32 chrome, Inter, canonical tokens, Android-identical glass shader and existing motion constants remain. Font/shader/token regression tests run. Historical portable NVDA evidence exists. | Matched Android visual captures and physical mixed-DPI / high-refresh display checks remain on hold; no physical-monitor parity claim. |
| M2 workspace | Existing multi-pane shell, dock, detail containers, pointer/keyboard queue controls and Mini-Player observe the same real host snapshot. Imported metadata and actual provider search results populate production views. | Full Android screen/interaction breadth is not complete. Local playlists/history/Encore summaries, real radio pages and automatic cached/provider lyrics are now connected; full podcast, story, download and Automix semantics remain in the Phase 3 parity register. There is no fixture catalog in the production JAR. |
| M3 decoders | Actual FFmpeg JNI reads MP3, FLAC, AAC/M4A, WAV/PCM and real provider WebM/Opus, converts to bounded Float32 stereo/48kHz decoder rings. Local seek equality is checked against decoded reference frames. | Eighteen real variants now pass full PCM/reference and seek comparisons, including independent HE-AAC v1/v2, ALAC and integer/float PCM. Corrupted/truncated/edit-list breadth and indexed low-latency long-file seeking still need hardening. No Java Sound or synthesized-audio production fallback. |
| M3 sink / DSP | Separate packaged JVM worker, two decoder decks, equal-power crossfade, existing desktop TPT EQ, smoothed gain/volume, limiter and real FFT feed native WASAPI shared output. Clock anchors use IAudioClock spans rather than wall-time simulation. | Full Android seven-manual/three-dynamic EQ parameter parity, Automix and pitch-preserving speed are later phases. 1.0x is the supported speed. Exclusive mode and bit-perfect device-native output are not enabled. |
| M3 lifecycle | Private bounded framed IPC, acknowledged commands, actor-owned host state, worker loss notification, at most three recovery attempts per 60 seconds, durable queue replay paused. | This is process isolation, not a native security sandbox. User/device matrix and extended soak testing remain. |
| M3 provider | Desktop resolves **InnerTubeX 0.11.2** (`innertubex-desktop-0.11.2.jar`, with QuackJS JVM 0.1.2 and Ktor 3.6.0), pinned by its own catalog entry `desktop-innertubex` and checked by `:desktop:verifyProviderJvm` (6 November 2026). Anonymous, read-only search/resolution and real SABR media acquisition. Public YouTube video search supplies playable catalog items when Music search returns only collections/profiles. A packaged full-track, post-60-second seek and actual next-track transition passed **on 0.7.2**. | All live provider evidence (search, resolution, SABR, seeks, downloads, the provider journeys in the Phase 3 status) was recorded on **0.7.2**: every frozen runtime up to 4 November 09:25 lists `innertubex-desktop-0.7.2`, and no evidence file lists 0.11.2. It does not carry over to 0.11.2; 0.11.2 has passed compile, unit tests and the provider graph check only, until the live provider journeys are re-run. Authenticated account/session features, all provider profiles, HLS and future challenge/protocol changes are not claimed. No fabricated URI, signed URL or credential is persisted. |
| M4 persistence | Real SQLDelight + SQLite JDBC session database, WAL/FULL, transactional bounded receipts, typed source identities with local SHA-256, duplicate occurrence IDs, queue/shuffle/repeat/settings, dual-deck position checkpoints and paused restart. Process-kill restore is tested. | Phase 2 now adds genuine scoped relational library/playlist/history/lyrics/catalog/art metadata, real FTS5 and quarantining legacy import with process-halt recovery. Account-authentication and complete phase acceptance remain open. `DesktopDatabase` is an old custom-file prototype kept only in test sources, never described as SQLite. |
| M4 caches | Production HTTP AVIO reads validated 206 ranges into disk-backed blocks, with bounded body/time budgets and no sparse-hole reads. SABR AVIO waits on actual downloaded bytes. | Representation-bound SHA-verified persistent blocks, 256 MiB quota, OS eviction leases and URL identity checks are now connected. Real artwork/palette acquisition persists across restart and opens with zero network fetches. SABR reconnect compares prior encoded bytes. Intentional offline download lifecycle remains unfinished. |
| M5 SMTC | Existing adapter/event-routing code exists. | It still does not publish a real WinRT SMTC media session/flyout. Native Windows media-flyout acceptance remains Phase 4. |
| M5 tray / power / keys / Discord | Coordinator and adapters exist; host playback changes feed existing integration callbacks. Discord remains disabled by default. | Actual native integration, state acknowledgement, Explorer/device recovery and configured Discord application identity need Phase 4 acceptance. Internal adapter state is not evidence of an OS effect. |
| M6 standalone image | Bundled JRE, UI launcher, separate RiffAudioWorker.exe launcher and FFmpeg/native DLLs are exercised by packaged acceptance; no installed JDK is used by that path. | Clean-machine Windows VM, MSI/EXE installer acceptance and Authenticode are Phase 5 gates. The historical MSI has not been accepted for the new native graph. |
| M6 updates | Existing offline signature/parser/freshness/compatibility/coordinator/signer security tests remain. Production defaults remain disabled. | Transport, staged payloads, Authenticode verification, installation helper, health handshake, rollback and live release configuration remain unfinished. |

Evidence has separate scopes: component tests, actual native/HTTPS/loopback tests, packaged local/provider/crash journeys, and the repository PR lane. A pass in one scope never substitutes for another. The direct dependency inventory is [SBOM](sbom.md); a complete native transitive license/source bundle remains a public-release gate.


Phase 2/3 details and current acceptance boundaries: [Phase 2](phase-2-status.md), [Phase 3](phase-3-status.md). On 3 November the corrected 90-second real-worker pilot passed with zero underruns, five actual seeks, worker heap peak 17,119,584 bytes and native process handles 673 to 675. This is a short pilot, not an eight-hour reliability pass. The real Phase 3 journey in `artifacts/desktop/phase3/real-journey-3.log` verified hardware playback, counted/deadline sleep stops, timer restart, live automatically acquired lrc.red lyrics and a real provider seek beyond 65 seconds. All nine repository PR gates passed separately. Latest package verification remains separately recorded rather than inferred from these results.
