# ADR 001: Desktop audio worker runtime

Status: superseded implementation decision, 2 November 2026. The original dual-mode Java Sound/synthetic-fixture decision is replaced by the production Phase 1 composition below.

Riff uses a **required packaged JVM worker with a native FFmpeg/WASAPI JNI bridge**. The UI process owns the serialized controller and durable desired session. RiffAudioWorker.exe launches the bundled Java runtime directly; it receives the chosen data directory explicitly and uses private stdin/stdout framing. A packaged app never selects an installed JDK or in-process engine when the worker is absent. In-process runtimes are explicit component-test dependency injection only.

The worker owns two bounded decoder rings and the Float32 mixer, EQ/gain/limiter and analysis thread. FFmpeg handles real local compressed containers or custom AVIO whose reader supplies validated HTTP ranges / SABR bytes. WASAPI shared output has a native event-driven MTA/MMCSS owner, a fixed one-second ring and about 150ms target producer lead. The sink is primed before playback acknowledgement; hardware clock spans exclude zero-filled underruns. FFT work follows presented post-DSP blocks, independently of Compose frames. Native decoding/network work never runs on the UI or native render thread.

Local seeking reopens and decodes forward to an exact decoded-frame offset. This intentionally trades late-seek speed for correctness in the first slice. Seek pauses the consumer, waits for real preroll, resets output/filter/timeline state and changes the epoch. Both active deck positions can be checkpointed and restored paused. Native stream-volume ramps and smoothed software master gain limit discontinuities; this does not imply all-device latency/quality acceptance.

Commands are correlated and acknowledged. The controller changes effective Playing after engine acknowledgement and observes authoritative position events. Worker loss stops effective playback. Recovery recreates only the owned worker, at most three times in a 60-second window, then handshakes and replays the durable queue paused. Pending failure is visible; the person can resume after recovery. SQLite WAL/FULL commits and receipts precede durable checkpoint acknowledgement; restart resolves stable provider IDs again rather than reusing signed URLs.

Request budgets are bounded: bridge operations 120 seconds, shutdown 5 seconds, mixer control 35 seconds, deck readiness/seek 30 seconds, provider resolve 90 seconds. Long work runs on the controller/decoder/IO owners, never synchronously inside Compose input handling. These are failure limits, not promised responsiveness targets.

Tradeoffs: JNI adds native crash risk and LGPLv3 provenance/source obligations; the worker confines a crash to playback and enables paused reconstruction. A second JVM increases measured process memory. The portable Zig/MinGW build replaces the proposed MSVC requirement on this laptop while retaining JDK21 JNI compatibility. No native dependency is silently substituted.
