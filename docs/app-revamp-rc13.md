# Riff 0.9.0-rc13

> **Historical record.** This document describes earlier work and is kept as it was written. It is not current documentation and may not match the code. Current documents: [documentation index](README.md). Current plan: [Riff excellence implementation plan](RIFF_EXCELLENCE_IMPLEMENTATION_PLAN.md).

Startup, player morphs, navigation, scrolling glass labels, artwork, button feedback, lyric emphasis and ambient palette transitions now avoid redundant composition or repeated work. The moving startup logo is drawn before app/provider initialization; the final reveal waits for the app's first layout. Its ribbon paths and glow brushes are reused. Artwork requests keep stable decode dimensions during morphs. Title glyph sizes are stable while layers scale. Player alpha and palette animation state is read in draw/layer callbacks. Navigation selector frames are isolated from navigation contents, and full-player geometry callbacks remain stable during morphs. Ambient palette changes and press scaling invalidate drawing layers. Scrolling category geometry only invalidates the glass layer and label overlay. Liquid and frost shader uniforms use separate shader instances, and category computations skip pixels outside their visible vertical band. Provider prewarming waits until after startup. Account-scope hashing is cached without changing its derivation. Playback snapshot encoding and periodic listening persistence use IO coroutines; lifecycle flushes retain the latest queue and position.

The capsule slider retains its appearance and a transparent, normally sized touch thumb. Physical testing also exposed an independent playback problem: existing MediaMuxer WebM files were not seekable through Media3 despite Android MediaExtractor accepting seeks. Local file playback now wraps only the Matroska extractor, providing a cluster timestamp/byte-position index when the standard seek map is unseekable. The index is read on the playback loader thread from bounded container headers. Audio bytes are never rewritten or re-encoded. Indexed files and other containers retain normal Media3 handling. Existing bundles immediately benefit without redownloading.

The provider's HTTP engine filters YouTube player responses before Innertubex codec/bitrate ranking. Explicit original-track metadata and encoded acont=original tags select the source audio across languages. Other quality variants with the same original track ID remain eligible. Dubbed and descriptive variants are excluded; manifest defaults cannot restore them. Ambiguous multiple-language and dub-only responses fail that client rather than silently selecting a dub, allowing the resolver to try another client. A single unlabeled response passes through because it supplies no identifying language information. Search, accounts, non-player requests and media bytes pass through unchanged. This policy depends on YouTube exposing audio-track identity; it cannot establish a source language that the provider does not identify.

Downloads is sorted by audio commit timestamp descending, with deterministic title/ID ties. Filters and its playback queue use the same collection order; listening does not reorder it. The hero still uses the newest downloaded artwork. Broken multi-encoded punctuation in Downloads, queue labels and playback status messages was repaired. App-owned Kotlin separators, bullets and ellipses use Unicode escapes, and the main source/resource scan contains no remaining mojibake patterns. Legitimate accents and provider text are retained.
